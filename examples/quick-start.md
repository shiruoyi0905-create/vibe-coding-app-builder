# Quick Start Examples

以下示例用于快速启动不同阶段的任务。替换方括号内容后使用。

## 从模糊想法开始

```text
Use $vibe-coding-app-builder。

产品想法：[一句话]
可能用户：[用户]
使用场景：[时间、地点、触发条件]
期望感受：[结果或体验]

先不要开发。请：
1. 找出最危险的 3 个需求/行为/技术假设；
2. 为每个假设给出最低成本验证方式；
3. 定义一条核心用户路径；
4. 将功能分为 P0/P1/P2；
5. 给出 Phase 0 是否通过的判断和理由。
```

## 已有原型，准备写 PRD

```text
Use $vibe-coding-app-builder。

原型位置：[链接或文件]
已观察到的用户反馈：[记录]
本轮目标：形成可直接指导实现的轻量 PRD。

请覆盖正常、加载、空、失败、重试和完成状态。
每个 P0 功能使用 Given/When/Then 写验收标准，
并列出非目标、数据与权限、成功指标和仍未解决的问题。
```

## 已有 PRD，准备开发

```text
Use $vibe-coding-app-builder。

PRD：[路径]
技术约束：[已有技术栈、运行环境、禁止事项]
本轮目标：[一条端到端用户价值]
验收命令：[例如 npm run lint、npm test、npm run build]
验收路径：[用户操作步骤]

先检查现有仓库，不要默认重建。
请提出最小垂直切片并实施；完成后报告改动文件、
实际执行的验证、结果和遗留风险。
```

## 精准修复一次体验问题

```text
Use $vibe-coding-app-builder。

设备/页面：[环境]
复现步骤：[步骤]
实际结果：[可观察现象]
预期结果：[可观察结果]
证据：[截图、视频或报错]
不得改变：[约束]

先复现并定位根因，再做最小修复。
补充防回归验证，不要顺手重构无关模块。
```

## 发布前检查

```text
Use $vibe-coding-app-builder 对这个项目做发布前阶段门检查。

仓库：[路径]
部署目标：[平台/环境]
核心路径：[步骤]
已知临时方案：[列表]

检查生产构建、环境变量与密钥、错误页、响应式、
可访问性基础、隐私与埋点、依赖和素材许可、生产复测、
README 和回滚点。只报告有证据的结果，将未验证项明确标记。
```
