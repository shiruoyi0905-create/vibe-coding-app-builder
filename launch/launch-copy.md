## 小红书 / 即刻

### 标题

我把“Vibe Coding 不跑偏”的方法，做成了一个开源 SOP + Codex Skill

### 正文

很多 Vibe Coding 项目不是写不出来，而是：

- 需求没想清楚就开始写代码
- 原型好看，但核心路径走不通
- PRD 太模糊，AI 每一轮都在自由发挥
- 一次改太多，出了问题不知道从哪里回退
- AI 说“应该能跑”，却没人真的测试

我把自己从 idea 到可运行 App 的流程整理成了 **Vibe Coding App Builder**：

1. 先定义问题和 MVP 边界
2. 用原型验证最危险的交互
3. 把行为写成可测试的验收标准
4. 按真实用户路径做垂直切片
5. 每轮都运行测试、构建和浏览器走查
6. 上线前补齐安全、隐私、文档和回滚

仓库里包含：

- 一份完整中文 Vibe Coding SOP
- 可直接安装的 Codex Skill
- 不同阶段的 Prompt 示例
- 多轮 AI 协作上下文模板

它不是“万能一键生成 App”，而是一套让 AI 编程项目更少跑偏、更容易验证和交付的方法。

GitHub：https://github.com/shiruoyi0905-create/vibe-coding-app-builder

如果你也在用 AI 做产品，欢迎试用后告诉我：你最容易在哪个阶段跑偏？

## V2EX

### 标题

[开源] Vibe Coding App Builder：从 idea 到可验证 MVP 的 SOP + Codex Skill

### 正文

做 AI Coding 项目时，我发现最大的成本通常不是写代码，而是需求漂移、上下文丢失、横向分层开发，以及缺少可观察的验收标准。

因此整理并开源了 Vibe Coding App Builder。核心是一套 7 阶段门流程：

- 问题与 MVP
- 体验原型
- 产品规格
- 技术方案
- 可验证开发
- 质量打磨
- 发布交付

仓库还包含可安装的 Codex Skill、Quick Start prompts 和上下文包模板。

项目地址：https://github.com/shiruoyi0905-create/vibe-coding-app-builder

欢迎对阶段划分、Skill 触发描述和实际使用体验提建议。
